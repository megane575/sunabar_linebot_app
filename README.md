## 1. アプリの基本要件（一つでも動く機能を作る）

- **MVP機能:**
  - LINEで「残高」と送ると、sunabar APIから取得した現在の残高を返信。
  - LINEで「収支」と送ると、今月の「収入合計」と「支出合計」収支の差額を計算して返信。
- **追加機能:** 1時間に1回（またはデモ用に5分に1回）、EventBridgeでLambdaを起動し、新着の入出金明細があればLINEに通知。

## 2. チーム開発のための技術要件（「共通のルール」）

### ① 開発言語と実行環境

- **言語:** Node.js (Version 20.x )
- **エディタ:** AWS Lambdaのコンソール画面、または各自のVS Code（Cursor）。
- **共有方法:** GitHubのリポジトリを1つ作成。
  - `main` ブランチ：常に動くコードを置く。
  - 作業用：各自の名前のフォルダを作って、そこでコードを管理。

### ② データ構造の共通化（インターフェース）

Bさん（API担当）が取得したデータを、Cさん（計算担当）がどう受け取るかを決めておきます。

> **例：取引明細の形式**
>
> `[
  { "type": "out", "amount": 5000, "date": "2026-03-24", "content": "コンビニ" },
  { "type": "in", "amount": 100000, "date": "2026-03-20", "content": "給与" }
]`
>
> この形（配列）でデータを渡すと決めておけば、BさんとCさんは独立して作業できます。

### ③ 環境変数の管理

APIのキーやトークンをコードに直接書かないルールを徹底します。

- AWS Lambdaの「設定」→「環境変数」に `LINE_ACCESS_TOKEN` や `SUNABAR_API_KEY` を登録し、コード内からは `process.env.XXXX` で呼び出すようにします。

## 3. 役割ごとの具体的な「成果物」

3日間という短期間を乗り切るための、各担当のチェックリストです。

### Aさん（インフラ・LINE）

- [ ] **Webhookの疎通:** LINE DevelopersでMessaging APIを設定し、Lambdaと繋いで「オウム返し」を成功させる。
- [ ] **メッセージ送信関数:** `line-bot-sdk` を使い、LambdaからLINEへメッセージを送る共通関数を作る。
- [ ] **タイマー設定:** EventBridge (CloudWatch Events) で定期的にLambdaを叩く設定を作る。

### Bさん（銀行API）

- [ ] **認証突破:** sunabarのアクセストークンを取得し、`axios` でAPIを叩けるようにする。
- [ ] **データ抽出:** 残高取得APIと明細取得APIを叩き、必要な数値（金額、日付）だけを抜き出す。
- [ ] **シミュレータ操作:** sunabarの管理画面でテストデータを追加し、コードが正しく反応するか検証する。

### Cさん（ロジック・計算）

- [ ] **合計計算:** Bさんが取ってきた明細配列を `filter` や `reduce` で回し、今月の「収入」「支出」を算出する関数を作る。
- [ ] **差分チェック:** （通知機能用）「前回の最新明細」と「今回の最新明細」を比較して、新しいものがあるか判定するロジックを作る。
- [ ] **メッセージ整形:** 返信用のテキストを「残高は〇〇円です！」のように読みやすく組み立てる。

## 4. Gitの使い分け

3名で開発する場合、**「コードをどこに書くか」**で迷うことがあります。

1. **個人の試行錯誤:** 自分のPCのVS Codeで書き、GitHubに `push` する。
2. **合体作業:** GitHubのコードをコピーして、AWS Lambdaのコンソールに貼り付けてテストする。

最初は「GitHubに上げたら自動でLambdaが変わる」という高度な設定（CI/CD）は**あえて目指さない**のが賢明です。手動コピペの方が、エラーが起きた時に原因を特定しやすいからです。
